# Contributing to ClimateOps

Thank you for contributing to ClimateOps. Contributions should improve climate-risk understanding, emergency awareness, or the reliability and accessibility of the platform.

## Before You Start

1. Read the [README](./README.md) and the relevant [project plan](./project_plan.md).
2. Check open issues and pull requests before starting duplicate work.
3. For substantial changes, open an issue first so the approach can be discussed.
4. Never commit API keys, credentials, personal data, or local environment files.

## Branches

- Keep `main` stable and suitable for review.
- Create a focused branch from the latest `main`.
- Use a descriptive name such as `feature/location-risk-summary`, `fix/alert-copy`, or `docs/data-sources`.
- Keep each pull request focused on one outcome.

## Pull Requests

Every pull request should:

- Explain the problem and the proposed solution.
- Describe user-facing or operational impact.
- Include documentation updates when behavior, setup, or data sources change.
- Include testing or manual verification steps.
- Call out configuration, migration, privacy, or safety implications.
- Avoid unrelated formatting or refactoring.

## Documentation Contributions

Documentation should:

- Use clear language and headings.
- Distinguish planned behavior from currently available behavior.
- Identify data sources, freshness, limitations, and ownership.
- Use absolute dates or explicit time zones when timing matters.
- Include recovery or fallback guidance for operational procedures.

## Review Standards

Reviewers will look for correctness, clarity, accessibility, privacy, reliability, and maintainability. Emergency-related guidance must not imply that ClimateOps replaces official warnings or professional emergency services.

## Reporting Problems

Do not report security vulnerabilities in public issues. Follow [SECURITY.md](./SECURITY.md). For bugs and feature requests, use the repository issue templates.
